# Knowledge Base

Personal reference notes on JavaScript, general programming, tools, and learning. See `index.md` for the folder map.

## Conventions

- Name files after the question/decision they resolve (`reduce-vs-for-loop.md`), not the API feature (`array.md`). Mental-model notes name after the concept instead (`closures.md`).
- Lead with the tradeoff or gotcha, then the example — syntax is a footnote, not the point. Assume the reader can look up syntax elsewhere; the note's value is the judgment call.
- Frontmatter on every file: `tags:`, `date:`, `type:` (`pattern` | `mental-model` | `gotcha` | `snippet`)
- Flat within each folder — avoid deep nesting
- Place new notes in the existing folder that best matches their topic (see `index.md`); update `index.md` if adding a new top-level folder
